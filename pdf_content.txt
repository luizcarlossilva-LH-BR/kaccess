1. LOGIN 
 
 
Devemos preencher a aba header com Authorization: Basic No body temos que enviar grant_type e scope 
 
URL: https://h.visitantes.online/auth/login/client 
Method: POST 
Header: Authorization: Basic <base64(client_id:client_secret)> 
Body: {“grant_type”:”client_credentials”, “scope”:”cloud-system-rw”} 
Response: 
 
O token retornado sempre será do tipo 
bearer, sendo que para as demais chamadas 
deve-se utilizar no Header:  
Authorization: Bearer eyJhG..... 
 
O atributo expires_in diz por quanto tempo o 
token é válido. No caso de client_credentials 
o valor padrão é 24 horas. 
 
É importante ressaltar que  não é possível se 
logar na interface gráfica utilizado 
client_credentials. 
 
E tanto client_id quanto client_secret serão 
fornecidos por nós.

3. BUSCAR ANFITRIÕES 
 
 
 
URL: https://api-
homol.visitantes.online/api/people/<companyInstanceName>/gf?&sort=name,asc&size=1000&name.contains
=&platformStatus.equals=IDENTIFIED&name.contains= 
Method: GET 
Header: Authorization: Bearer <token obtido no login> 
Body: NA 
Essa API deve trazer os colaboradores validados (platformStatus.equals=IDENTIFIED) podendo filtrar usando 
primeiro e ultimo nome, então para buscar alguém chamado “John doe” utilizamos o filtro 
“&name.contains=john&name.contains=doe”. 
A busca sempre trará uma lista, ainda que possa ser uma lista vazia ou  até com um único elemento. O dado 
importante do colaborador é: refId. Ele deverá ser utilizado para gerar o evento no campo hostRefId conforme 
explicado acima no item 2.
